# 通用学习文档写作规范

此 skill 用于生成高质量的中文技术学习文档，以 **概念清晰 + 代码可运行 + 数学有讲解** 为核心目标。

## 整体结构

文档使用 Markdown 配合 KaTeX 数学公式。结构要素：

1. **标题（# 🎯 标题）** — 用 emoji 点缀，一句话点明主题
2. **引言（无编号）** — 点明为什么学这个、它在知识体系中的位置
3. **目录导航** — 章节超过 3 个时加表格形式的导航
4. **正文小节** — `## 1. 小节标题` → `### 1.1 子标题`
5. **📊 全景对比** — 文末总结表格
6. **📚 参考资料** — 文献链接

## 🌈 趣味性要求

**emoji 使用规范**：
- 每个 `##` 标题前加 1 个主题 emoji
- 关键洞察用 `> 💡 **一句话总结**：...`
- 对比表表头可用 emoji 辅助表意
- 不要过度使用，正文段落中 2-3 段放一个即可

## 🧭 概念引入的衔接

**硬要求**：每个新知识点的定义之前，必须有衔接段落。采用「**简洁定义 → 要素拆解 → 具体领域例子佐证**」的结构。

示例格式（内容为示意）：
```
### 1.1 什么是 XXX

在 X 领域，**XXX** 被定义为一种 YYY 的方法。

要理解 XXX，需要拆解 N 个关键要素。首先是**要素一**——它的作用和含义。
其次是**要素二**——它控制着……。最后是**要素三**——实际计算方式。

以 [具体领域场景] 为例：[说明 XXX 如何在该场景中发挥作用、解决什么问题]。
```

**关键**：引入时用一个具体、真实的领域场景来驱动理解。领域例子取自：自动驾驶、量化交易、图像分类、LLM 训练、推荐系统等实际场景。**禁止使用日常生活比喻。**

## 📐 数学公式规范

- 每个公式后必须有通俗解读
- 逐一解释每个符号的含义和典型取值
- 关键公式用 `> 📖 **解读**：...` 单独说明

格式模板：
```
$$公式$$

其中：
- 符号一 — 含义，典型取值
- 符号二 — 含义，典型取值

> 📖 **直观理解**：用自然语言一句话概括公式的意图。
```

## 💻 代码规范

**硬要求：代码必须是完整可运行的，严禁伪代码或占位符。**

- ` ```python ` 标注，函数需要 docstring 说明参数和返回值
- 每段代码附带实际运行输出
- 长代码按逻辑拆成多段，每段配一段解释文字

## 📋 表格规范

- 对比总结用表格，列数 3-6 列
- 表头简短，内容中可用 ✗ ✓ 辅助表意

## 🗺️ 内容组织流程

按以下结构展开每个方法。步骤 4-6 为**条件性步骤**，仅当主题涉及数学运算或编程时才包含；若主题为纯概念性内容，用其他等价方式替代。

**必选步骤**（所有主题）：
1. 📖 **简洁定义** — 「在 X 领域，Y 被定义为...」
2. 🔗 **要素拆解** — 将定义拆成 3-4 个关键要素逐一解释
3. 🎯 **具体例子** — 用一个真实领域场景贯穿说明

**条件性步骤**（有数学/代码时才包含）：
4. 📐 **数学公式** + 符号逐一讲解 —— 仅当主题有公式时包含；无公式则跳过
5. 🧮 **手算示例** —— 仅当有数学公式时包含；无公式则用**流程图、对比表、时间线或结构化枚举**替代
6. 💻 **完整代码** —— 仅当主题涉及可编程内容时包含；无代码则用**配置示例、架构图文字描述或步骤拆解**替代

**必选步骤**（所有主题）：
7. ✅⛔ **优势与局限** — 文字形式，结构如下：
   - **优势**：1-2 句简要概括，不展开
   - **局限**：至少 3 条。每条用 `**① ...** ` 开头，3-5 句深入分析——描述现象、量化后果、说明在何场景下最严重
   - **承上启下**：以 `> 🔗 **承上启下**：` 开头，明确指出下一节方法如何解决上述局限。必须同时关联本节和下一节的具体技术点，不能写空泛过渡
   - 适用范围广时，局限需覆盖「陷入局部最优/鞍点」
   - 最后一个方法收束到「进化终点总结」

**替代说明方式**（当无法用数学/代码时）：
- 流程图 → 用 ASCII art 或文字描述决策分支
- 对比表 → 列举不同方案在各维度的表现
- 时间线 → 按发展顺序列出关键节点和里程碑
- 结构化枚举 → 将复杂概念分解为互斥完备的分类层次

```

[引言 2-3 段]

| 章节 | 核心问题 |
|------|---------|
| 1. 方法A | 它解决什么问题 |
| 2. 方法B | 它解决什么问题 |
| ... | ... |

---

## 1. 方法A

### 1.1 什么是方法A（定义 → 要素拆解 → 领域例子）
### 1.2 数学公式（有公式时；无则跳过）
### 1.3 手算推导（有公式时；无则用流程/对比/枚举替代）
### 1.4 代码实现（有代码时；无则用配置/架构描述替代）
### 1.5 优势与局限（文字形式，含承上启下）

## 2. 方法B
...

---

## 📊 全景对比

| 特性 | 方法A | 方法B | ... |
|------|-------|-------|-----|

## 🎯 选择指南

[决策树或文字建议]

## 📝 小结

## 📚 参考资料
```

## ❌ 严禁出现

- 生活化比喻
- 伪代码、`pass`、`...`、`# TODO` 占位符（包括 skill 自身的示例中）
- 没有解释裸放公式
- 直接给定义无衔接过渡
- 第一人称或针对本任务的引用
- 过长的单行公式（超 80 字符应换行）
- 技能文档自身夹杂具体领域文档内容
