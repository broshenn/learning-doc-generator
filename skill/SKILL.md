# 通用学习文档写作规范

此 skill 用于生成高质量的中文技术学习文档，以 **概念清晰 + 代码可运行 + 数学有讲解** 为核心目标。

---

## 整体结构

文档使用 Markdown 配合 KaTeX 数学公式。结构要素：

1. **标题（# 🎯 标题）** — 用 emoji 点缀，一句话点明主题
2. **引言（无编号）** — 点明为什么学这个、它在知识图谱中的位置
3. **目录导航** — 章节超过 3 个时加表格形式的导航
4. **正文小节** — `## 1. 📌 小节标题` → `### 1.1 子标题`
5. **📊 全景对比** — 文末总结表格
6. **📚 参考资料** — 文献链接

## 🌈 趣味性要求

**emoji 使用规范**：
- 每个 `##` 标题前加 1 个主题 emoji（如 💡🔑🚀🧠⚡🔥📌)
- 代码块旁不加 emoji
- 关键洞察用 `> 💡 **一句话总结**：...`
- 对比表中可以在表头用 emoji 辅助表意
- 不要过度使用，正文段落中 2-3 段放一个即可

## 🧭 概念引入的衔接

**硬要求**：每个新知识点的定义之前，必须有衔接段落。概念引入采用「**简洁定义 → 要素拆解 → 具体领域例子佐证**」的结构。

❌ 错误写法：
```
### 1.1 动量法
动量法是一种优化方法，公式如下：
$$v_t = \beta v_{t-1} + (1-\beta)g_t$$
```

✅ 正确写法（用具体领域例子展开）：
```
### 1.1 🧠 什么是动量法

在探索任何一个复杂概念时，最好从一个简洁的定义开始。
在优化领域，**动量法（Momentum）** 被定义为一种利用历史梯度
的指数加权移动平均来平滑参数更新方向的方法。

要理解动量法，需要拆解三个关键要素。首先是**速度累积** $v_t$——
优化器在参数空间的每一步不再只看当前梯度，而是维护一个"速度"
变量，将过去多步的梯度信息保留下来。其次是**衰减系数** $\beta$，
它控制着旧速度与新梯度的权重分配：$\beta=0.9$ 意味着每一步保留
90% 的旧方向，仅用 10% 的新梯度来微调。最后是**更新规则**——
参数的实际更新量由速度 $v_t$ 而非原始梯度 $g_t$ 决定。

以一个具体的训练场景为例：在深度网络的峡谷形损失面上，
SGD 会在峡谷两侧来回震荡，每一步只能沿谷底方向前进极小距离。
动量法在此场景下，垂直于谷底方向的反复震荡相互抵消（速度均值≈0），
而沿谷底方向的持续梯度被不断累积——就像一个滚下山坡的雪球，
横向晃动被自然过滤，向下的速度却越来越快。
```

**关键：引入时用一个具体的、真实的领域场景来驱动理解，不要用生活化比喻。**
领域例子可以是：自动驾驶、交易算法、图像分类、LLM 训练等实际场景。

## 📐 数学公式规范

- 每个公式后必须有**通俗解读**
- 逐一解释公式中每个符号的物理含义和典型取值
- 对于关键公式，用 `> 📖 **解读**：...` 单独说明

格式模板：
```markdown
$$公式$$

其中：
- $\beta$ — 动量系数，通常取 0.9，控制历史速度保留的权重
- $v_t$ — 第 $t$ 步的累积速度
- $g_t$ — 第 $t$ 步的梯度

> 📖 **直观理解**：$\beta$ 越接近 1，历史方向的影响力越强；
> $\beta=0$ 时退化为普通 SGD。
```

**硬要求：代码必须是完整可运行的，严禁伪代码或占位符（`pass`、`...`、`# TODO`）。**

- 标注语言：` ```python `、` ```bash `
- 函数需要 docstring 说明参数和返回值
- 附带一个微型运行示例并展示实际输出
- 输出用实际打印结果标注

## 📋 表格规范

- 对比总结用表格，列数 3-6 列最佳
- 表头简短，内容中可以加 checkmark ✗ ✓

## 🗺️ 内容组织流程

按以下结构展开每个方法：

1. 📖 **简洁定义** — 「在 X 领域，Y 被定义为...」
2. 🔗 **要素拆解** — 将定义拆成 3-4 个关键要素逐一解释
3. 🎯 **具体例子** — 用一个真实领域场景贯穿说明
4. 📐 **数学公式** + 符号逐一讲解
5. 🧮 **手算示例** — 一个超小例子手动推一遍
6. 💻 **完整代码** — 可运行，含测试输出
7. ✅⛔ **优缺分析** — 用表格对比

## ❌ 严禁出现

- 生活化比喻（如「就像滑雪下山」「摸着石头过河」）
- 伪代码、`pass`、`...`、`# TODO` 占位符
- 没有解释裸放公式
- 直接给定义无衔接过渡
- 第一人称或「本次任务」「这篇文档」
- 过长的单行公式（超 80 字符应换行）
